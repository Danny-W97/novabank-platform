PIERWSZE URUCHOMIENIE / LOKALNE PLIKI
Przygotuj środowisko z panelu
Control Center utworzy brakujące .novabank/env/project.env i dev.env. Uzupełnij dane tutaj, zapisz, a potem uruchom kolejne kroki poniżej.
Zapis nie uruchamia baz ani aplikacji. Istniejące prawidłowe hasła baz i klucz szyfrowania 2FA są chronione przed rotacją. Puste pole sekretu zachowuje jego wartość; brakujące hasła i klucze zostaną wygenerowane. Jeżeli baza była już inicjalizowana, a utracono plik z hasłem, odtwórz poprzednie poświadczenia — nowy sekret w pliku nie resetuje hasła w bazie. Zmiany wymagają późniejszego restartu aplikacji.
Wymagane są wcześniej przygotowane narzędzia WSL: Python 3, JDK 25 i Docker Engine. Panel nie instaluje ich i nie wykonuje sudo.

        
Kreator podstawowego DEV
Ustawienia TEST zmienisz w „Pliki i sekrety”, a test.env utworzysz w Operacje. PROD, Vault i certyfikaty pozostają poza edytorem.

LOKALNE USTAWIENIA / DEV I TEST
Konfiguracja bez szukania plików
Wybierz plik po lewej. Możesz zmieniać ustawienia, dodawać pola, usuwać je oraz jawnie podejrzeć sekret na 45 sekund. Sekrety są domyślnie ukryte; puste pole sekretu zachowuje wartość.
Zapis zmienia pliki, nie hasła w istniejącym PostgreSQL ani działające procesy. Nowy klucz TOTP bez migracji uniemożliwia odszyfrowanie wcześniej zapisanych sekretów 2FA. Klucz API musi być zgodny w banku i sklepie. Zmiany wymagają restartu zależnych usług. Plików nie edytuj równocześnie w IDE/CLI. Nigdy nie wpisuj tutaj sekretów PROD.
TEST przekazuje wyłącznie pola TEST_* do testów Maven. Testcontainers może nadpisać adresy baz. Monitoring i backupy DEV nie są uruchamiane w widoku TEST.

Zanim rozpoczniesz
  1. Sprawdź narzędzia WSL w Operacje → Narzędzia.
  2.  Utwórz podstawowe pliki. Zaawansowane ustawienia i sekrety zmienisz w „Pliki i sekrety”.
  3. Uruchom bazy, wykonaj buildy i uruchom aplikacje. Nie zajmuj tych samych portów dwoma procesami.
  4. TEST uruchamia testy Maven z test.env; integracyjne korzystają z Testcontainers. Nie przełącza baz DEV na TEST.
  5. Monitoring, Stripe TEST, backupy i DR baz DEV mają osobne kategorie Operacji.
  6. PROD ma osobne jawne procedury Vault/AppRole, bootstrap/TLS i buildy. Każde zadanie wymaga wpisania PROD. Inicjalizacja Vault, token operatora i dane KV wymagają administracyjnego przygotowania poza panelem.
CLI nadal działa: bash scripts/start.sh --cli. Instalacje wymagające interaktywnego hasła administratora muszą być zatwierdzone w systemie, nie w formularzu WWW.

Potwierdź operację

    

    
Operacja może zmienić lokalne pliki, procesy lub kontenery. Zamknięcie karty nie przerywa zadania.

    
UWAGA — URUCHAMIASZ OPERACJĘ PROD. Może zmienić Vault, dostęp aplikacji, pliki bootstrap lub certyfikaty. Upewnij się, że wybrano właściwe środowisko. Zmiany nie są automatycznie cofane; procedury Vault/TLS trzeba doprowadzić do wyniku i sprawdzić przed ponowieniem.

    

    
Pola są ukryte i używane tylko w tym zadaniu. Nie trafiają do historii, logów, URL ani localStorage. Nie wpisuj tokenu root. Panel obsługuje lokalny HTTPS Vault 127.0.0.1:8200 z CA projektu; nie zdalną produkcję.
